# 前端技术文档编写指南

以下四类为前端常见负责需求类型：

1. PC端
2. H5端 （非客户端）
3. Groot系统
4. BMS后台系统

## 技术文档基础信息部分

以下内容为必须包含，是文档的基础信息：

```md
|所属业务|小陪伴|
|---|---|
|需求负责人|产品：<br>开发：|
|需求文档||
|设计稿||
|埋点|无埋点需求|
|飞书项目迭代地址||
|灯塔迭代||
|部署地址||
|分支||
|接口文档||
```

## 项目与更改

接下来的部分需要对具体项目单独展开，一个项目需要包含：

```md
# 项目名称，例如：Groot系统，BMS后台

## 说明

结合需求文档，简要阐明需要实现哪些需求，对需求进行分解与说明等

## 组件/文件修改

### 需求1：xxx

|修改组件|列表形式展示某个需求需要改哪些组件的组件地址|
|---|---|
|修改文件|列表形式展示某个需求需要改哪些文件的文件地址（修改的文件不包含上面的组件）|
|改动说明|简要说明需求需要对哪些代码进行改动，提炼要点，修改范围。<br>**UI改动需列出字段名、控件类型（如Select/Switch/Slider等）、默认值**|
|注意事项|修改当前代码是否可能导致哪些问题，需要注意什么，是否可能影响其他的业务|
|图例|前端一般为UI给出的修改图片，这里保持为空即可，待用户自己填入|

### 需求2: xxx
...

## 接口

|接口名称|函数|方法|URL|参数|调用时机|兼容说明|
|---|---|---|---|---|---|---|
|接口名称一般从代码注释中读取，如果没有直接使用函数名|代码中可以直接索引到的函数名|GET/PUT/DELETE/POST...|后端真实请求url地址，无需携带preUrl,如：/api/v1/user即可|入参|代码中何时会调用这个接口，可以直接提供文件地址+行号|是否复用现有接口、是否需要新增、是否影响存量功能|

|---|---|---|
|功能名称|绝对路径，如：`/path/to/component.vue`|该文件实现的核心功能简要说明|
```
